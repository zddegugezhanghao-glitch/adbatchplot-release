## 3. 为什么浩辰定位不到 Plotters

### 3.1 现有实现只有两条来源

`AcadPlotterInstaller.GetAutoCadPlotterDirectory()`（浩辰档与 AutoCAD 档同源）：

```
1) GetExistingPrinterConfigDirectories()
   └─ ReadPreferenceFilesPath("PrinterConfigPath")
      └─ 反射： typeof(CadApp).InvokeMember("AcadApplication")        ← 关键
              → .Preferences → .Files → .PrinterConfigPath
2) GetSystemVariableString("ROAMABLEROOTPREFIX")                       ← AutoCAD 专有系统变量
```

任何一步拿到结果才会返回目录；两条都空 → 返回 `""` → 直接 `return`，**不会再尝试随包模板目录**。

### 3.2 实测：浩辰的 COM 属性名与 AutoCAD 不同

对浩辰官方 SDK 程序集做元数据枚举（`_tools/sdkprobe/gstar_probe/`）：

| 程序集 | 含 `Application` 的属性 |
|---|---|
| 浩辰 `GcCoreMgd.dll`（20.25） | `IsApplicationContext` —— **没有 `AcadApplication`** |
| 浩辰 `GcMgd.dll`（20.25） | **`AcadApplication`**、`ApplicationIcon`、`ApplicationStatusBarMenu`、`ApplicationToolbarsMenu` |
| 中望 `ZwManaged.dll`（net47） | **`AcadApplication`**、`ZcadApplication`、`IsApplicationContext` … |

关键点：

- 浩辰把 COM 入口叫 **`GcadApplication`**（`GcCoreMgd` 里出现 17 次），`AcadApplication` **只在 `GcMgd.dll` 里有**。
- 当前代码走哪个程序集取决于 `ACAD_CORE` 符号：
  ```csharp
  #if ACAD_CORE
  using CadApp = Gssoft.Gscad.ApplicationServices.Core.Application;   // → GcCoreMgd，无 AcadApplication
  #else
  using CadApp = Gssoft.Gscad.ApplicationServices.Application;        // → GcMgd，有 AcadApplication
  #endif
  ```
- 实测：**`ACAD_CORE` 在主工程、旧版工程、中望工程、生成的浩辰工程里都没有定义**（`grep` 全部为空），所以应当走 `#else`。但这条路径是否能真正反射成功，取决于浩辰 `Preferences.Files` 是否暴露 `PrinterConfigPath`——**这一点无法离线确认，需实机验证**（见第 5 节）。

### 3.3 结构性差距：浩辰线缺少中望线已有的多路兜底

| 探测手段 | AutoCAD 档 | **浩辰档** | 中望档 |
|---|---|---|---|
| `...Preferences.Files.PrinterConfigPath`（COM） | ✅ | ✅ | ✅ `ZWCAD/AcadPlotterInstaller.cs:473` |
| `GetSystemVariableString("ROAMABLEROOTPREFIX")` | ✅ | ✅ | ✅ `:434` |
| `GetSystemVariableString("**PrinterConfigDir**")` | ❌ | ❌ | ✅ `:474` |
| `GetSystemVariableString("**PrinterDescDir**")` | ❌ | ❌ | ✅ `:510` |
| `GetSystemVariableString("**PrinterStyleSheetDir**")` | ❌ | ❌ | ✅ `:546` |
| 随包模板目录（`FindBundledPlotterRoot`） | 仅用于取模板，**不用于兜底目标目录** | 同左 | 同左 |

> 中望线是这份源码的"原生平台"，所以它写得多路兼容；**浩辰线是从 AutoCAD 线派生的**，只继承了 2 条。这就是浩辰更容易失败的根因。

### 3.4 兜底逻辑的设计缺陷

`AcadBatchPlot.Installer` 明明有随包模板（`resources/gstar/Plotters/PIA2/AD_pdf.pc3` + PMP），`FindBundledPlotterRoot()` 也已经把它找到了（`AcadPlotterInstaller.cs:43`），但紧接着第 59 行找不到"目标 CAD 目录"就 `return`——**模板找到了却没地方写**，于是整条链路失败。这属于"**该降级不降级，直接报错**"。

## 4. 会造成"崩溃闪退"的薄弱点

> 用户在截图之外还报了"崩溃闪退"。截图本身是**被捕获**的异常（有 MessageBox），所以闪退另有来源。以下是逐项排查结果。

### P0-1　全工程无全局异常兜底

```
grep -rn "UnhandledException|DispatcherUnhandledException|UnobservedTaskException|SetUnhandledExceptionMode" --include=*.cs
→ 0 命中
```

插件以 `NETLOAD` 方式跑在 CAD 进程内：

- **UI 线程**未捕获异常 → WPF 会直接终止进程（默认策略）；
- **后台线程 / Timer / 异步续体**未捕获异常 → `AppDomain.UnhandledException`，无处理器即崩溃。

只要有一个路径漏了 `try/catch`（下面几条都是候选），表现就是"CAD 突然消失"，且**不留任何日志**，用户无法反馈有效信息。

**这是与"闪退"最直接对应的薄弱点。**

### P0-2　浩辰版被当作"中望版"编译（`#if ZWCAD` 污染）

`_tools/build_gstar.py:79` 为浩辰构建定义 `ZWCAD`：
```xml
<DefineConstants>$(DefineConstants);ZWCAD</DefineConstants>
```
这样 `Common/**` 里 42 个 `#if AUTOCAD … #else` 会正确落到"非 Autodesk"分支。**副作用是：7 个带 `#if ZWCAD` 专有分支的文件，浩辰全部走进"中望专有"逻辑。**

实测受影响项：

| 文件 | 浩辰实际走的分支 | 应为 |
|---|---|---|
| `Common/Services/Paper/PmpCustomPaper.cs` | **10 处 `#if !ZWCAD` 全被剔除** | 应保留（浩辰是 pc3/pmp） |
| `Common/Infrastructure/CadMenuInstaller.cs` | `PreferredMenuGroupName = "ZWCAD"` | `GStarCAD` |
| `Common/Infrastructure/CommandAliasManager.cs`、`TitleBlockLibraryStore.cs` | 走中望分支 | 需逐个确认 |
| `Common/Services/Scanning/{CadTextExtractor,CadTextUpdater,TianzhengTextReader}.cs` | 走中望分支 | 需逐个确认 |

**最严重的是 `PmpCustomPaper`**：被剔除的正是 PIA3(JSON) 处理（`RegisterPia3` / `RemovePia3`）。而实测：

```
resources/gstar/Plotters/PIA3/PMP Files/AD_pdf.pmp   ← 文件头 PIAFILEVERSION_3.0（PIA3 / JSON）
resources/acad/Plotters/PIA3/PMP Files/AD_pdf.pmp    ← 同上
resources/zwcad/Plotters/PMP Files/AD_pdf.pmp        ← PIA2（中望 pc5 体系）
```

→ 浩辰注册"满版零边距自定义纸"时，**拿到的是 PIA3 PMP 却只有 PIA2 解析器**：轻则注册静默失败（满版失效），重则把 PMP 写坏（后续出图报错）。这条能解释一类"莫名失败 / 异常"。

### P0-3　中望资源"文件名改了、内部没改"（用户已指出 LA_pdf）

逐字节实测（`resources/zwcad/Plotters/`）：

| 文件（磁盘名） | 内部 `LA_` 次数 | 具体内容 |
|---|---|---|
| `AD_pdf.pc5` | **1** | `[Standard] LocationName=LA_pdf` |
| `PMP Files/AD_pdf.pmp` | **65** | `paper_local_name0..64 = LA_A4 / LA_A3 / LA_A4_1.25L / LA_A3_3.75L …` |

对照组（干净）：

| 资源目录 | pc3/pmp 内部 `LA_` | 说明 |
|---|---|---|
| `resources/acad/Plotters/` | **0** | PIA2/PIA3 均为 `AD_` |
| `resources/gstar/Plotters/` | **0** | 从 acad 目录复制，随改名一起更新 |
| `resources/zwcad/Plotters/` | **66** | ← **唯一漏改的一套** |

代码侧已完全清除：`src/` 下 `.cs` 中 `LA_` 命中数为 **0**（全部改为 `AD_`）。
→ **只剩中望这套绘图仪资源内部还是旧名。**

可观察后果：

1. 中望打印对话框里那 65 个纸型显示为 `LA_A4`、`LA_A3`…，与产品名 `AD-批量打印` 不一致（观感问题）；
2. `LocationName=LA_pdf` 会让设备信息里出现旧名；
3. **更实际的风险**：老版本已在用户机器上装过 `LA_pdf.pc5`（绑定 `LA_pdf.pmp`），升级后插件往 `AD_pdf.pmp` 写自定义纸。用户若在设备列表里选了残留的 `LA_pdf`，就会出现"纸张列表里找不到刚注册的满版纸"→ 出图报错。

**好消息**：`LA_` 与 `AD_` 都是 3 字节，属**等长替换**，可原地字节级改写，文件大小与内部偏移完全不变，零风险。

### P1-1　旧版（AutoCAD 2007–2012）预览走模态窗直调 PlotEngine

| 版本 | 预览做法 |
|---|---|
| 新版（2013–2027） | 非模态主窗 → `PendingPlotPreview.Start` → `SendStringToExecute("_ZBP_INTERNAL_PREVIEW")` **进命令/文档上下文**；代码注释明确写了"按钮事件处于应用上下文，直接 Preview 会假启动" |
| **旧版（2007–2012）** | `LegacyBatchPlotCommands.cs:56` `CadApp.ShowModalDialog(form)`（**模态**）→ `LegacyBatchPlotForm.cs:613` **直接** `PlotterService.Preview(job, device, style, _document)` |

模态 WinForms 消息循环期间，CAD 的文档命令上下文无法推进，而 `PlotEngine` 的交互预览需要它。这是典型的"**在模态对话框里跑需要命令上下文的同步阻塞操作**"，在 R18（2010–2012）上出现死锁、重入或原生崩溃的风险明显高于新版。**这条与"AutoCAD 2012 闪退"的怀疑方向吻合，但目前是推断，需实机复现。**

### P1-2　部署目录混入历史 `LA_*` 模板

实测：

```
C:\ADONG\dist\Plotters\PIA2\        AD_dwf/png/jpg/pdf.pc3  +  LA_dwf/png/jpg/pdf.pc3   ← 新旧混杂
C:\ADONG\dist\Plotters\PIA2\PMP Files\   同时有 AD_*.pmp 与 LA_*.pmp
C:\ADONG\dist\Plotters\PIA3\        AD_pdf.pc3 / LA_pdf.pc3
C:\ADONG\dist2025\Plotters\PIA2\    只有 LA_*.pc3 / LA_*.pmp   ← 没有 AD_pdf.pc3！
C:\ADONG\dist2025\Plotters\PIA3\    只有 LA_pdf.pc3
```

- `dist2025`（net8 档、对应 AutoCAD 2025–2027）**随包模板里没有 `AD_pdf.pc3`**，而 `FindBundledPlotterRoot()` 正是按 `Plotters\PIA2\AD_pdf.pc3` 探测 → 该档必然报 **"未找到随插件附带的 AD_pdf 打印机配置。"**
- 用户 CAD 的 `%AppData%\Autodesk\AutoCAD 2020 / 2026\...\Plotters\` 里也留着 16 个 `LA_*` 旧设备（`LA_pdf.pc3` 等），构成上面 4.3 节说的"选错设备"风险。

### P2　其余不一致（低危，但影响可诊断性）

- 浩辰档多处的提示文案仍写 `AutoCAD`（如 `未能定位 AutoCAD Plotters 目录`），误导用户与售后定位；
- 浩辰档 `CadMenuInstaller.PreferredMenuGroupName = "ZWCAD"`；
- `AutoloadManager` 依赖 `HostApplicationServices.Current.UserRegistryProductRootKey`（各平台取值不同；浩辰 `GcDbMgd` 中有该成员，但实际返回路径需实机确认）；
- `AcadPlotterInstaller.EnsureRasterDpi` 是按 **AutoCAD pc3** 的字段名（`res_color_mem.resolution` 下 `effective / addr / phys_resolution_x|y`）写的，而**中望 pc5 的字段名是 `resolution_x / resolution_y`**（本次实测 pc5 全文确认）→ 中望档的 DPI 写入需单独核对，否则可能"设了不生效"。

## 6. 改进方向（可直接落地）

### A. 加全局异常兜底（最高优先级，成本最低）

在 `IExtensionApplication.Initialize()` 里挂上：

```csharp
AppDomain.CurrentDomain.UnhandledException += (s, e) => LogAndNotify(e.ExceptionObject as Exception);
// WPF 档：
Application.Current.DispatcherUnhandledException += (s, e) => { LogAndNotify(e.Exception); e.Handled = true; };
TaskScheduler.UnobservedTaskException += (s, e) => { LogAndNotify(e.Exception); e.SetObserved(); };
```

写 `%TEMP%\ADBatchPlot_error.log`（含时间、CAD 版本、调用栈），并**只提示一次**。
→ 把"无声闪退"变成"可上报的错误 + 明确日志"，是后续所有问题的前提。

### B. Plotters 目录定位改为"多源探测 + 取第一个命中"

把中望线已有的思路推广到三平台，探测顺序建议：

1. COM `Preferences.Files.PrinterConfigPath`（属性名按平台取值：AutoCAD/中望用 `AcadApplication`，浩辰可先试 `GcadApplication` 再试 `AcadApplication`）；
2. 平台系统变量：`ROAMABLEROOTPREFIX` → `PrinterConfigDir` → `PrinterDescDir` → `PrinterStyleSheetDir`；
3. 从 CAD 主模块路径推导 `<install>\Plotters`（`acad.exe` / `gcad.exe` / `ZWCAD.exe` 所在目录的子目录）；
4. 扫描 `%AppData%\{厂商}\…\Plotters`（按平台厂商名）；
5. **最后回退到随包模板目录**（本地 `Plotters`），以"能用"优先。

### C. 定位失败时**不要抛异常**，改为降级

`CustomPaperBatchPreparer.Prepare` 目前是 `throw`。建议改为：

- 记录日志 + 状态栏/清单列提示"本机未找到打印机配置目录，已改为普通出图（不使用满版零边距纸）"；
- **让出图流程继续**，而不是整条预览/出图链路中断。

用户拿到"能出一版"的结果，远比拿到一个 MessageBox 有用；同时也不会因为异常逃逸而闪退。

### D. 浩辰改为独立符号 `GSTAR`，不再复用 `ZWCAD`

```
#if ZWCAD      → 中望 pc5 专有
#elif GSTAR    → 浩辰 pc3/pmp 专有（尤其是 PIA3 处理）
#else          → AutoCAD
```
涉及 7 个文件。重点补回 `PmpCustomPaper` 的 PIA3 分支，并把菜单组名、文案、资源路径一并参数化。
（代价：`build_gstar.py` 的投影改为定义 `GSTAR` 而不是 `ZWCAD`，并把 `#if !ZWCAD` 改为 `#if !ZWCAD` → `#if AUTOCAD || GSTAR` 之类的等价表达。）

### E. 中望资源做等长字节替换 `LA_` → `AD_`

```python
# LA_ 与 AD_ 同为 3 字节 → 文件大小/偏移不变，零风险
for f in [r'resources\zwcad\Plotters\AD_pdf.pc5',
          r'resources\zwcad\Plotters\PMP Files\AD_pdf.pmp']:
    d = open(f, 'rb').read()
    open(f, 'wb').write(d.replace(b'LA_', b'AD_'))
```
涉及 66 处（1 + 65）。改完重编中望三档即可。

### F. 安装/部署侧的清理与校验

- 插件安装时把打印机目录里的 `LA_*`（pc3/pc5/pmp）**移到备份子目录**（不直接删），并在状态栏提示"检测到旧版 LA_* 绘图仪，已备份到 …"；
- 重新生成部署目录时，**AD_* 模板必须齐套**（当前 `dist2025` 缺 `AD_pdf.pc3`，会导致该档不可用）；
- 设备枚举（`RefreshPlotterDevicesIfNeeded`）之后**校验目标设备确实存在**，不存在则明确报"设备未注册"而不是继续往下走。
