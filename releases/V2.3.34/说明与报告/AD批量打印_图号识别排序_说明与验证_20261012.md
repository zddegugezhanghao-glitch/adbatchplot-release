# AD-批量打印 · 图号识别排序 说明与验证（第二版）

版本：V2.2.13 · 2026-10-12（第二轮迭代）

## 一、图号识别怎么用

无图框定义时（矩形识别 / 无框识别都行），从**图框内的文字**里抓图号，再按图号排序。

1. 工具栏「排序设置」→ 排序依据选 **按图号**（已从原来的「按图号（图号 + 图名）」改名，
   排序主序**只用图号**，图名只在图号相同时打平局）。
2. 下方展开「图号识别」区，勾「启用图号识别」，然后二选一：
   - **选图号文字 / 框选图号区域** —— 窗口里两个按钮，点完回图面取样本。
     学习后**会弹确认窗口**，显示归纳出的样式、样本、位置锚点；可以改样本，也可以点「重选文字 / 重框区域」再学一遍，确认后才生效。
   - **手输样式** —— 填示例（`D-01`）或规则（`D-\d+`）；多条用**逗号、顿号或换行**分隔。
3. 点「测试匹配」试算：会报「命中 N / M 张」，并把识别到的图号**按自然序排出来**给你看
   （D-01、D-02、D-10…），顺序对不对一眼可辨。试算**不改清单**，可以反复试。
4. 点「确定」→ 就地重算（不重扫几何）→ 清单立刻更新并重排。

### 学习图号的两种捕捉方式（都在窗口里点按钮，不用敲命令行）

| 按钮 | 何时用 |
|---|---|
| **选图号文字** | 图号是独立文字或块属性，能直接点中。可多选，回车结束 |
| **框选图号区域** | 图号夹在标题栏里不好单独点中。两点框住那一格即可，可连续框多个，回车结束 |

框选区域时，若区域内混进了图名/比例/日期，程序会按启发式挑出最像图号的那一条，不会把噪声当样本。

### 未识别的图号

自动**排到最后**、整行**标黄**、提示列写「⚠ 图号未识别」、状态栏报数。手动补填后重排即可。
（降序时也不会把这些翻到最前面。）

## 二、本轮修掉的问题

| # | 你反馈的现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 手输图号识别"没成功"，只有框选学习有用 | 输入被顿号分隔时（`D-01、D-02`），整串被当成**一条**样本，归纳出的正则里带上了顿号字面量，之后一个图号都匹配不上 | 顿号按分隔符处理；归纳不出样式时状态行会明确说"该怎么写" |
| 2 | 识别了图号，清单图号列没更新 | 图号/图名列的显隐由"本批有没有图号身份"决定，而这个标记只在扫描时算过一次 —— 扫描之后再设置图号规则，标志没重算，列一直是隐藏的 | 重算后同步重算该标记、切换列显隐、刷新行与文件名 |
| 3 | 「按图号（图名+图号）」这个名字不对 | 文案与排序语义不一致 | 下拉项改为「按图号」；主序只用图号 |
| 4 | 学习完没有确认环节 | 学习后直接落库 | 新增确认窗口：可看样式、改样本、重新学习 |
| 5 | 学习只能选对象，不能框选 | 只实现了选择集方式 | 增加「选择文字 / 框选区域」两种方式 |
| 6 | 窗口标题版本显示不对 | 标题是「AD-批量打印 · 批量打印 V2.2.13」，产品名里已含"批量打印"，重复 | 改为「AD-批量打印 V2.2.13」 |
| 7 | **新增图框点「确定」入库失败、CAD 闪退** | 见下节 | 加固 + 加流程追踪 |
| 8 | **图号识别出来了，但清单「图号」列全空**（值跑到文件名去了） | 字段列模板绑的是 `Binding("FieldValue")`，而 `FieldValue` 是**方法不是属性** —— WPF 取不到路径，**所有字段列（图号/图名/日期/版次/自定义字段）一直是空的**。值其实早就采到了，文件名都用它命名了，只有清单这块看不见 | 给 `Row` 加索引器并把列改绑 `['字段Key']`；补上索引器刷新通知（`Item[]`），重算后列才会跟着变 |
| 9 | 图号/图名列的显隐控制从未生效 | 判断条件是 `SortMemberPath == "DrawingNumber"`，但字段列的 SortMemberPath 实际是 `"FieldText:DrawingNumber"`，永不相等 | 建列时登记「列 → 字段Key」映射，显隐按映射判断 |
| 10 | **新增图框后，「图框库」里看不到** | 图框库界面只在新增**返回成功**时才刷新列表；保存失败 / 你没确认 / 重名选了「否」这几种情况下列表纹丝不动 —— 看起来就是"点了确定没录入"，但到底是没保存成还是没刷新，无从分辨 | 改成**无条件刷新**列表（成功就能看到新图框，失败也无害）；「确定」返回非确认、或入库异常时都会写日志并在命令行说明原因 |
| 11 | **排序点「确定」后 CAD 致命错误**（`e0434352h`，和第一轮同一个地址） | 重算图号时会**遍历整张图的全部实体**，但原先只包了"取实体"那一步；后面读 `Layer`、`Position` 等属性时只要有一条代理实体/异常对象抛错，异常就穿出命令上下文 | 改为**逐条实体独立兜异常**（图上一条读不出字没关系，崩掉不行）；块定义文字、录入图框的文字读取同样逐条兜 |
| 12 | 学习图号要在命令行敲 S/W，不符合使用习惯 | 用了 CAD 关键字提示 | 改成窗口里两个按钮：**选图号文字** / **框选图号区域**；确认窗口里的重学也拆成「重选文字 / 重框区域」 |
| 13 | **"有些字体识别不了"** | 录入图框时读文字只走**一层**块嵌套，而且只读块属性、**不读块定义里的普通文字** —— 而图号/图名常常就是直接画在标题栏块里的文字，藏在"图框块→标题栏块→文字"两三层里，于是什么都读不到 | 嵌套深度放宽到 3 层，并补上块定义文字的读取（坐标按块变换转到世界坐标） |

## 三、关于新增图框闪退（需要你配合一次）

"直接闪退、连提示都没有"说明崩溃**没有走托管异常路径**（否则 CAD 会先弹「致命错误」框），
所以日志里通常什么都不会留下。这一轮我做了三件事：

1. **加固了最容易出问题的三处**：临时红框的清除（`TransientFrameMarkers`）、窗口关闭时交还焦点、
   异常提示改为延迟弹出（不再在异常处理器里同步弹模态框 —— 那会重入消息循环）。
2. **「确定」按钮整条链路包了异常兜底**，异常会被记下来而不是穿出去。
3. **加了流程追踪开关**，用来定位"走到哪一步断的"：

```
在系统里新建环境变量：  AD_BATCHPLOT_TRACE = 1
重启 CAD  →  复现一次闪退  →  把下面的日志发我：

  %TEMP%\ADBatchPlotTrace.log     ← 流程追踪（走到哪一步断的）
  %TEMP%\ADBatchPlot_error.log    ← 异常日志（如果有托管异常）
```

追踪日志看得出这类信息，直接指向故障点：

```
15:04:22.118  新增图框：命令开始
15:04:25.402  显示 CAD 模态窗：FieldFrameDialog
15:04:31.870  CAD 模态窗返回：FieldFrameDialog → True
15:04:31.881  新增图框：字段对话框已确定，开始读取结果
15:04:31.905  新增图框：字段与纸张已解析，准备写入图框库
← 到这里就没了 = 崩在图框库写入
```

拿到日志前，这条只能算"大幅加固"，还不能说根治 —— 我不想给你一个"应该好了"的结论。
