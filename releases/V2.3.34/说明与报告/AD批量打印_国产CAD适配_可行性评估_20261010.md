# ADONG 批量打印 — 国产 CAD 适配可行性评估

> 评估日期：2026-10-10
> 评估对象：中望 ZWCAD、浩辰 GStarCAD
> 参考文档：https://www.gstarcad.com/sdk_doc/ 、https://www.zwsoft.cn/support/zwcad-devdoc
> 结论：**可以，且中望这条线已经编通（0 错误）**

---

## 一、结论（先说结果）

| 平台 | 可行性 | 当前状态 |
|---|---|---|
| **中望 ZWCAD** | ✅ 极高 | **已实编译通过**，产物 `bin\BatchPlotter.dll`（897,536B，md5 `a8c7f0982bf75cf2b46407c02d29d2ae`） |
| **浩辰 GStarCAD 2024–2027** | ✅ 高 | 需新增一条平台线，工作量约同"再加一代 AutoCAD" |
| 浩辰 GStarCAD ≤2023 | ⚠️ 中 | 用的是旧 API（`gmap/gmdb`），属另一代接口，建议不做或最后做 |

**最关键的一条**：这套源码**原本就是中望 CAD 插件的源码**（工程名 `batchPrintZWCAD`），ZWCAD 那条线从 `#if` 分支到独立平台目录**全部保留在仓库里**，从未删除。所以"适配中望"几乎不是新开发，而是**把原有的线重新接上**。

## 二、三条硬证据

### 证据 1：源码里的中望线完好无损

```
src/BatchPlotter/BatchPlotter.csproj      ← 原版中望工程（DefineConstants=ZWCAD）
    <Compile Include="..\Common\**\*.cs" />
    <Compile Include="..\ZWCAD\**\*.cs" />          ← 中望平台实现目录
    <PackageReference Include="ZWCad.Net.2025" Version="1.0.0" ExcludeAssets="runtime" />

src/ZWCAD/                                 ← 11 个文件，与 AutoCAD/ 一一对称
    AcadPlotterInstaller.cs / AutoloadManager.cs
    Plotter/PlotterService{,.Documents,.Media,.MultiFile,.Pipeline,.Scale,.SystemVariables,.Window}.cs
```

- `Common/**` 中 **42 个文件**带 `#if AUTOCAD … #else … #endif`，`#else` 分支写的就是 `ZwSoft.ZwCAD.*`
- 另有 7 个文件带 `#if ZWCAD` 专有分支（菜单安装、命令别名、图块库、PMP 自定义纸、天正文字读取等）
- 中望侧命名空间用量：`ApplicationServices` 55 / `DatabaseServices` 52 / `Geometry` 34 / `EditorInput` 14 / `PlottingServices` 9 / `Runtime` 6 / `Colors` 3 / `GraphicsInterface` 1

### 证据 2：中望官方 SDK 包可直接从 NuGet 还原

```
包 ID：ZWCad.Net.2025   版本 1.0.0   （与源码 csproj 引用一字不差）
内容：lib/net47/  →  ZwManaged.dll(4.6MB) / ZwDatabaseMgd.dll(8.6MB)
                     ZwSoft.ZwCAD.Interop(.Common).dll / ZcCui / ZcWindows / ZdWindows
```

同名系列另有 `ZWCad.Net.2023`、`ZWCad.Net.2024`，**三年都是 `lib/net47`、同一组程序集**。

### 证据 3：实编译结果 —— 0 错误

```
dotnet build src/BatchPlotter/BatchPlotter.csproj -c Release
→ EXIT=0，0 个错误，16 个警告
→ bin\BatchPlotter.dll   PE32+/x64   AssemblyRef: ZwManaged v25.0.25.0
                                                  ZwDatabaseMgd v25.0.25.0
```

首次构建仅报 **10 个错误**，且全部是**我们自己做 2013–2027 适配时留下的残留**（AutoCAD 专有的 `NativePlotStamp` / `PlotTiming` / `WarmUpPlotPipeline` 被写进了共享视图），**不是中望 API 缺失**。已按对称方式补齐 3 个中望空实现垫片 + 把 `SettingsForm` 里的全限定 `Autodesk.AutoCAD.EditorInput.*` 改为平台中立写法，随后 0 错误通过。

### API 代际核对（决定复用哪条代码路径）

本项目出图靠 `PlotEngine` / `PlotSettingsValidator` / `PlotInfo` / `PlotConfigManager` / `PlotProgressDialog` / `LayoutManager`，以及 `FileOpenMode` / `SpatialFilter` / `MLeaderStyleDictionaryId` 等。逐项核验结果：

| 符号 | 中望 2025 | 浩辰 2026 |
|---|---|---|
| `PlotEngine` | ✅ | ✅ |
| `PlotSettingsValidator` | ✅ | ✅ |
| `PlotConfigManager` | ✅ | ✅ |
| `PlotProgressDialog` | ✅ | ✅ |
| `FileOpenMode` | ✅ | ✅ |
| `SpatialFilter` | ✅ | ✅ |
| `MLeaderStyleDictionaryId` | ✅ | ✅ |

**两家都是 AutoCAD 2013+ 代际的 API 面**，不是 R17(2007) 那套老 API。这意味着：

- **中望 2023–2025** ↔ 复用 **net48 那条线**（2013–2024 代码路径）
- **浩辰 2024–2025** ↔ 复用 **net48 那条线**
- **浩辰 2026–2027** ↔ 复用 **net8 那条线**（2025–2027 代码路径）

本项目为 2007–2012 做的那套 `#if NET35` 兜底**完全不需要**用在这两家上。

## 五、浩辰要做什么（工作量评估）

中望几乎没有新增代码，浩辰则要**新增一条平台线**，做法与现有 `src/ZWCAD/` 完全同构：

| 步骤 | 内容 | 量级 |
|---|---|---|
| 1 | 新建 `src/GStarCAD/`，以 `src/ZWCAD/` 为模板：11 个文件，把 `ZwSoft.ZwCAD.` → `Gssoft.Gscad.`，引用换成 `GcMgd/GcDbMgd/GcCoreMgd` | 机械替换 |
| 2 | `Common/**` 的 42 个 `#if AUTOCAD … #else` 由二分支扩为三分支（`#if AUTOCAD #elif ZWCAD #else /*GSTAR*/`） | **可用脚本机械化**，参考已用过的 `swap_ifaces.py` 手法 |
| 3 | 7 个 `#if ZWCAD` 专有分支补 `GSTAR` 分支（菜单安装、命令别名、PMP 自定义纸、天正文字等） | 逐个核对，最费人工 |
| 4 | 新增 `AcadBatchPlot.GStar.csproj`（net48）与 `.GStar2026.csproj`（net8），指向同一套源码 | 复制现有 csproj 改包名 |
| 5 | 编译迭代，处理真实 API 差异 | 参照中望经验：预计个位数到十几处 |

**关键判断**：浩辰的活与我们刚做完的"2007–2012 + 中望"是同一类工作——**搭平台骨架 + 编译迭代消化 API 差异**。中望从 10 个错误到 0 只用了 4 个文件；浩辰因为要新增整个平台目录，量级更大，但风险同型。

## 六、风险与注意事项

1. **NuGet 包非官方发布**：`ZWCad.Net.2025`（作者 `Ctc727`）、`GStarCad.Net`（作者 `vicwjb`）都是社区重新分发的包，**包里装的是原厂签名 DLL**（含 `.signature.p7s`），但包本身不是原厂发布。正式交付建议**改用 CAD 安装目录里自带的程序集**（如 `C:\Program Files\Gstarsoft\GStarCAD2026\GcMgd.dll`）做最终验证。
2. **无真机验证**：本机没有装中望/浩辰，上述结论均为**编译级验证**（引用解析、API 面、元数据）。运行时行为（NETLOAD、菜单、出图驱动）需在装有对应 CAD 的机器上实测。
3. **AutoCAD 侧 md5 已变**：为让共享视图不再写死 `Autodesk.*`，我改动了 `Common/Views/SettingsForm.xaml.cs`（4 处全限定名去前缀，**行为等价**，且顺带让中望也能用「图幅捕捉」）。回归验证通过：
   - `AcadBatchPlot.dll`（net48）`acbb96ba…` → `96b3de28…`
   - `AcadBatchPlot2025.dll`（net8）`f96eea36…` → `d6907fa4…`
   - 2007 legacy 线 `18243a06…` 未受影响（0 错误）
   - → **现有发布包已略过时，建议重出一版**。
4. **中望侧沿用 WPF**：ZWCAD 2025 是 net47（.NET Framework 4.x），能跑 WPF，因此**中望版保留完整 WPF 界面**，不像 2007–2012 那样必须重写 WinForms。这是好消息——中望版功能可与 AutoCAD 版完全对齐。
5. **`ExcludeAssets="runtime"`**：中望宿主程序集不会被拷进 `bin\`（已核验），运行时由 ZWCAD 提供，符合插件规范。

## 附：本次用到的核验手段

- `dnfile` 解析托管程序集：AssemblyRef / TypeDef / 命名空间分布 / 程序集版本
- 原始 PE 头解析：`0x3C → e_lfanew → +24` 读 magic 判定 PE32(x86) / PE32+(x64)
- NuGet flat-container API 枚举版本、下载 `.nupkg` 后直接列 `lib/<tfm>/` 与 DLL 清单
- 构建日志解析：按 `error CSxxxx` 分类，区分"引用解析失败"与"真实 API 差异"
